## API protection review

Already present:

- AI SDK tool-aware schema validation and Zod input/output schemas.
- Maximum 50 messages and 8,000 text characters per message; final message from user.
- Server-owned system instructions, provider key and model configuration.
- 4,096 output tokens per step; three model steps; 60-second Vercel function duration.
- Abort propagation for Stop/disconnect, supported by `vercel.json`.
- Safe user-facing provider errors; repair of malformed/stopped tool history.

Added in FE-11:

- Read and cap the actual body at **256 KiB**, including UTF-8 bytes and chunked
  bodies with false/missing Content-Length, before JSON/schema/model work.
- Reject non-JSON media types, malformed UTF-8/JSON, client system/developer roles,
  empty user messages, unsupported parts (including files/URLs), and user tool parts.
- Limit 32 parts per message and count text/reasoning parts together; run full SDK
  tool validation after the bounded envelope checks.
- Per-instance, synchronous fixed-window burst admission: **10 requests/IP/minute
  on Vercel**, or **60/minute in one shared bucket** when no trusted IP is available.
  Count configured requests before parsing, including invalid ones.
- Use only Vercel's `x-vercel-forwarded-for` when `VERCEL=1`; other hosts ignore
  forwarded headers. Ephemeral HMAC keys avoid storing/logging raw IPs.
- Bound storage to 5,000 active identities, prune expired entries, and reject new
  identities when full rather than evicting an active budget.
- Return plain-text 429 with `Retry-After`; mark errors `Cache-Control: no-store`.
  Rate admission does not buffer or alter the outgoing SSE stream.
- Log mapped provider errors rather than raw provider request objects.
- Refuse Vercel builds if the local-only sabotage flag is enabled.

**Limit:** process memory is not distributed storage. Cold starts reset budgets;
parallel instances and regions have independent counters. Shared IPs/NAT can share
limits. This is useful for trivial repeated requests, not an authenticated/global
quota or spend ceiling. Provider-side spending limits and an optional distributed
store/platform rate rule are needed for stronger guarantees. No paid infrastructure
or platform firewall configuration was added.

Vercel header assumptions follow its
[request header documentation](https://vercel.com/docs/headers/request-headers).

The Windows sandbox crashed Firefox before any application navigation; an
unsandboxed blank-page diagnostic succeeded, followed by the full Firefox suite.
An isolated native-HTML reproduction showed this Windows WebKit build skips
implicit link tab stops, even with Alt+Tab, but honors explicit `tabIndex={0}`.
Both hero CTAs now use explicit zero tab stops, preserving DOM focus order and
allowing the same plain-Tab regression check on all three browser engines.
WebKit also exposed typing before React hydration. The composer is now disabled
until handlers are attached, following
[Playwright's hydration guidance](https://playwright.dev/docs/navigations#hydration).
The Stop regression uses the scripted slow response so its control remains
available while the browser performs native click/scroll actionability checks.
The playground regression opens the modal with Enter from an explicitly focused
trigger; it verifies restoration of prior keyboard focus without assuming a
mouse click focuses a button in every browser.

WebKit is engine-level compatibility coverage, not a test of branded Safari or
physical iOS/macOS devices. Hidden-tab testing dispatches `visibilitychange` with
an overridden visibility state; it verifies the renderer's handler, not an OS-level
browser backgrounding policy. Pointer checks exercise input and continued rendering,
not a pixel-perfect assertion about glow appearance.

## Security and history

`node scripts/security-review.mjs --include-build` checks working source and
reachable Git history for recognizable OpenRouter/OpenAI, Google, GitHub, AWS and
private-key patterns. It also verifies `.env.local` is ignored/untracked/absent from
reachable history, checks public assets against the local API-key value in memory,
and looks for scripted-response strings in normal public assets. It prints paths,
never matching credential values. A pattern scan does not rule out every secret.
The final normal build manifest explicitly records the sabotage flag as `0`;
the public-asset scan found neither the local API-key value nor scripted response
text. Config regression tests confirm Vercel rejects an enabled test flag.
Hosted CI's default shallow checkout only exposes the history fetched there;
the local audit inspected all locally reachable revisions.

Existing history is clear and chronological: Conventional Commit `feat`, `fix`,
`test`, `perf`, and `chore` milestones follow one initial bootstrap commit.
No rewrite or force-push is warranted or performed.
